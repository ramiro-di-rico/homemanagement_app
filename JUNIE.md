## Skills

Task-specific procedures live in `.junie/skills/<name>/SKILL.md` (symlinks to
`.claude/skills/`, the single source of truth). Read the matching one **before**
starting the task — each records gotchas not visible from the code:

| Skill | Read it when |
|---|---|
| `flutter-new-feature` | Adding a resource/screen end-to-end |
| `flutter-call-backend-endpoint` | Adding or changing any HTTP call |
| `flutter-add-cached-data` | Caching a response, or fixing stale data after a write |
| `flutter-add-route` | Adding a route, public route, or deep link |
| `flutter-add-locale-string` | Any change introducing user-facing text |
| `flutter-mobile-desktop-variant` | A screen needs a distinct desktop layout |
| `flutter-theme-and-styling` | Picking colors or app-wide appearance |
| `flutter-write-widget-test` | Adding test coverage |
| `flutter-release-build` | Cutting a release build |

Do not add generic Flutter skills here. Four of them used to live in this folder
and were removed: they described Flutter in the abstract rather than this repo,
and one of them (`flutter-build-responsive-layout`) actively contradicted how this
codebase handles desktop layouts. A skill earns its place here only by recording
something specific to this codebase.

## Non-negotiables

1. Never hand-edit `lib/l10n/app_localizations*.dart` — generated by `flutter gen-l10n`.
2. Never add `@injectable` / `@Injectable()`. DI codegen is **not** wired up; all
   registration is by hand in `registerServices()` / `registerSingletons()` in
   `lib/main.dart`.
3. Views call repositories, never services directly.
4. Match the file-naming convention of the folder you edit — this repo mixes
   `kebab-case.dart`, `dot.separated.dart`, and `snake_case.dart`.
5. Mobile and desktop full screens are separate widget trees selected in
   `lib/routing.dart`, not one responsive widget with breakpoints.
6. A new public route must be allowlisted in the `redirect` guard in
   `lib/routing.dart`, or it silently redirects to login.
