# AGENTS.md

Guidance for AI coding agents working in this repository. The authoritative
architecture notes live in [CLAUDE.md](CLAUDE.md); this file is the shared entry
point and the index of task-specific skills.

## Skills

Detailed, repo-specific procedures live in `.claude/skills/<name>/SKILL.md`.
Read the matching file **before** starting one of these tasks — each one records
gotchas that are not visible from the code alone.

| Skill | Read it when |
|---|---|
| `flutter-new-feature` | Adding a new resource/screen end-to-end (service → repository → DI → view → route) |
| `flutter-call-backend-endpoint` | Adding or changing any HTTP call |
| `flutter-add-cached-data` | Caching an API response, or fixing stale data after a write |
| `flutter-add-route` | Adding or changing a GoRouter route, public route, or deep link |
| `flutter-add-locale-string` | Any change that introduces or edits user-facing text |
| `flutter-mobile-desktop-variant` | A screen needs a distinct desktop/web layout |
| `flutter-theme-and-styling` | Picking colors or changing app-wide appearance |
| `flutter-write-widget-test` | Adding test coverage |
| `flutter-release-build` | Cutting a release build for Android or Linux |

Skill discovery per tool:

- **Claude Code** — reads `.claude/skills/` natively.
- **OpenCode** — reads `.claude/skills/` natively, no extra configuration.
- **Junie** — reads `.junie/skills/`; the entries there are symlinks to
  `.claude/skills/`. If your checkout does not support symlinks (Windows without
  `core.symlinks=true`), read `.claude/skills/` directly.
- **GitHub Copilot** — see `.github/instructions/*.instructions.md`, which scope
  the key rules by path and point at the full skill files.

`.claude/skills/` is the single source of truth. Edit a skill there; never edit a
copy or a symlink target elsewhere.

## Non-negotiables

1. **Never hand-edit `lib/l10n/app_localizations*.dart`.** They are generated by
   `flutter gen-l10n` and your edits will be overwritten silently. Edit the
   `.arb` files and regenerate.
2. **Do not add `@injectable` / `@Injectable()` annotations.** `injectable` is a
   listed dependency but codegen is not wired up. All DI is registered by hand in
   `registerServices()` / `registerSingletons()` in `lib/main.dart`.
3. **Views call repositories, never services directly.**
4. **Match the file-naming convention of the folder you are editing.** This repo
   mixes `kebab-case.dart`, `dot.separated.dart`, and `snake_case.dart` across
   features. Mirror the neighbouring files; do not introduce a fourth style.
5. **Full-screen mobile vs. desktop layouts are separate widget trees** selected
   in `lib/routing.dart`, not one responsive widget with breakpoints.
6. **A new public route must be allowlisted in the `redirect` guard** in
   `lib/routing.dart`, or it silently redirects to login.
